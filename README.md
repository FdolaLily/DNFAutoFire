- 弹出设置页中的单键绑定统一改为点击输入框后直接按键，并支持 Delete、方向键和数字小键盘等特殊按键。
- 一键奔跑改用事件令牌确认输入意图：初次按下立即行走，默认持续 140ms 后只补一次抬起/按下，约 170ms 即可进入奔跑；350ms 内的不同方向序列优先按搓招处理，短促的技能输入也会永久取消本次待触发，避免轮询漏键。
- 奔跑确认阶段的抬起/再次按下采用原子提交，斜向第二方向会在首方向恢复按下后再处理，避免恰好卡在双击间隔时丢失一个移动轴。
- 最终奔跑按下提交后立即建立连续移动会话，不再额外等待 350ms；仍按住旧方向时新增正交方向会直接继承奔跑且不补双击，相反方向或短暂全松后的重新起步使用 90ms 异步确认，快速乱动不会再把方向热键压在等待线程后面。
- 技能释放后的奔跑恢复由主进程执行，只处理已经确认的奔跑会话；斜向会话选择最近方向重触发一次，不再把搓招中仍按住的方向误当成奔跑。
- 最终连发模式使用 10ms 按下 + 10ms 抬起，单键用于探索单技能释放极限。
- 同时按下两个或三个连发键时，按当前配置顺序使用固定 8ms 协同相位；四键以上回退动态错峰，不绑定具体键位。
- 战法炫纹发射键限定为数字小键盘按键，并提示使用时先按住发射键，再按 Num Lock 关闭数字小键盘。

## 自动构建与 GitHub Releases

[下载最新版本](https://github.com/FdolaLily/DNFAutoFire/releases/latest) · [查看构建记录](https://github.com/FdolaLily/DNFAutoFire/actions/workflows/build-release.yml)

- 推送 `main`、推送 `v*` 标签或在 Actions 中手动运行 `Build and Release`，都会在 Windows 上自动编译并运行全部回归；提交到 `main` 的 Pull Request 也会验证构建，但不发布。
- 只有推送 `v*` 标签（例如 `v0.3.0.1`）才会发布 GitHub Release：构建通过后读取根目录 `Version` 的 `tag_name` 和 `body` 创建 Release，标签必须与 `Version` 一致。推送 `main` 只编译、测试并上传 Actions 构建产物，不再每次都发布。
- 附件包含 `DNFAutoFire.exe`、Windows x64 ZIP 和 `SHA256SUMS.txt`。Actions 的构建产物保留 30 天；Release 附件长期保留。失败的构建不会发布，上传中断会保留草稿，可对同一提交重新运行。
- 发布前校验标签、EXE 与 manifest 版本一致，校验 Zig 下载包和编译器的固定 SHA256，并执行已知检出样本黑名单检查。自动检查不等于杀毒软件主动扫描通过。
- 版本号自动递增：本机运行 `scripts/build.ps1` 时，只要编进 EXE 的源码（`native/` 下的 .cpp / .h / .rc / manifest、图标、字体）与上次定版时不同，第四位自动加一（0.3.0.1 → 0.3.0.2），并同步 `Version`、`native/version.h`、`native/client.manifest`；源码没变则不加，编译失败会退回原版本号。`native/version.h` 是代码里唯一的版本来源（版本资源、`kProductVersion`、界面版本号都取自它）。要升级前三位时运行 `scripts/bump-version.ps1 -Set 0.4.0.0`；`-NoVersionBump` 构建不改版本。CI 只校验三处版本一致，发现源码变了却没升版本时给出警告。
- 发布新版：确认 `Version` 的 `body` 和本文件更新日志写好后，`git tag v<版本> && git push origin v<版本>`。
- 云端工作流使用 GitHub 托管 runner 与内置 `GITHUB_TOKEN`，无需配置个人令牌。本机 `E:\autokill`、`AutoManagerProcess` 的部署继续使用 `scripts/publish.ps1` 完成。

## 功能简介
 - 多键位无冲突连发
 - 不影响打字
 - 仅DNF游戏窗口内激活
 - 自动使用管理员模式启动
 - 效能媲美Wegame内置连发(基于个人测试)

## 服务管理

v0.3.0.0 起不再需要单独的 `DNFProcessManager.exe`、`服务管理.bat` 和 .NET 运行环境。`DNFAutoFire.exe` 同时承担两个角色：

- 平时双击打开的是连发界面；
- 安装服务后，Windows 以 `DNFAutoFire.exe --service` 在后台运行同一个程序，不显示窗口。

### 第一次使用

1. 把 `DNFAutoFire.exe` 放到一个固定的目录，例如 `E:\autokill`。旧版目录里的 `config.ini`、`appsettings.json` 保留在原处即可。
2. 双击运行，允许管理员权限。首次启动会把旧配置合并为 `config.json`，成功后自动删除旧文件，底栏会提示结果。
3. 点击主界面“启动连发”开关左侧的 **后台服务** 状态打开“服务管理”，点击 **安装并启动**。已经装过旧版 DNFProcessManager 服务时，这里显示 **更新并启动**，会先停止并删除旧服务，再安装新服务。
4. 看到“后台服务 运行中”即完成。状态灯：绿灯 = 服务正常运行；黄灯 = 需要更新（服务注册的是其他位置的程序，或旧版服务待替换）；红灯 = 服务未安装或未运行。底栏和键盘指示区的“连发”灯同理：绿灯运行中，红灯未启动。

之后每次启动 DNF，服务会在游戏所在的登录会话中以管理员权限打开连发（不会再弹出 UAC 提示）；DNF 退出后，连发先自行停止并释放按键，再关闭。

移动程序目录前请先在“服务管理”中卸载服务，移动后再重新安装，否则 Windows 仍会寻找旧位置的 EXE。卸载只删除 Windows 服务，不删除程序、配置和日志。

**删除 / 移动时提示“文件正在使用”**：服务运行时一直占用 `DNFAutoFire.exe`，所以 Windows 会拒绝删除或移动。提示框里显示的占用者就是服务名“DNF 连发后台服务（删除或移动程序前：打开连发 → 后台服务 → 卸载）”，照做即可：双击打开 `DNFAutoFire.exe` → 点“启动连发”左侧的 **后台服务** → **卸载**（再点一次确认）→ 在托盘图标右键菜单点 **退出**，然后就能删除。也可以在管理员命令提示符中执行 `sc stop DNFAutoFire` 和 `sc delete DNFAutoFire`。服务每次启动时会把显示名称和说明刷新为当前版本的文字。

### 更新程序

服务和托盘里的连发都会占用 `DNFAutoFire.exe`，所以不能在资源管理器里直接覆盖。更新有两种方式，效果相同：

- **双击新版本**：把下载好的新 `DNFAutoFire.exe` 放在任意位置（例如“下载”文件夹）双击。程序发现已安装的副本（服务注册的 EXE，或正在运行的连发）时会询问“将已安装的 DAF 连发工具更新到 v…？”，选 **更新已安装的程序** 即可；选“暂不更新”则照常打开。
- **从文件更新**：在“服务管理”的 **程序版本** 卡片点 **从文件更新…**，选中新版本文件，核对版本后点 **确认更新**。

更新时依次：经服务管理器停止后台服务 → 通知连发自行停止并释放按键（5 秒未退出才强制结束）→ 用新文件覆盖已安装的程序（先改名再换入，任何一步失败都恢复原文件、不留半个文件）→ 打开新版本 → 重新启动服务。已安装的位置、`config.json`、日志和服务设置都不变，不保留旧版本文件，新版本底栏提示“已更新到 v…”。目标路径只取自服务注册信息或正在运行的程序，不写死任何目录；所选文件必须是 DAF 连发工具（按版本资源识别）。版本号更低时会提示“降级”，默认按钮为“暂不更新”。

### 从旧版组合升级（AHK 连发 + DNFProcessManager 服务 + INI）

旧版发布包是一个文件夹里的 AHK 版 `DNFAutoFire.exe`、.NET 服务 `DNFProcessManager.exe`、`config.ini`、`appsettings.json`、`服务管理.bat` 和 `DNF专用工具箱8.0.bat`。升级只需 **双击新的 `DNFAutoFire.exe`**（放在任何位置都可以）：程序按已安装的旧服务找到它启动的连发（`appsettings.json` 的 AutoStart，默认同目录的 `DNFAutoFire.exe`），或找到正在运行的 AHK 版，询问“将旧版 DAF 连发工具和 DNFProcessManager 服务升级到 v…？”，选 **升级旧版** 后依次：

1. 停止旧服务 DNFProcessManager / AutoManagerProcess；
2. 关闭旧版连发（向 AHK 主窗口发送关闭，让它自己释放按键；5 秒未退出才强制结束，包括它的按键子进程）；
3. 用新程序替换原位置的 `DNFAutoFire.exe`（失败恢复原文件）；
4. 打开新版本：`config.ini` 与 `appsettings.json` 合并为 `config.json`，校验成功后删除（旧服务若不在连发目录，其设置会先移到连发旁边再合并，AutoStart 改为绝对路径）；
5. 安装新的后台服务 DNFAutoFire 并删除旧服务；
6. 旧服务确认删除后，删除 `DNFProcessManager.exe`（及 `.pdb`）、`服务管理.bat`、`DNF专用工具箱8.0.bat`（工具箱已内置）、`appsettings.Development.json` 和旧服务日志 `logs\auto-manager*.log`。两个 bat 只在内容确属旧版时删除，其他文件（如旧版 README）不动。

也可以手动把新 `DNFAutoFire.exe` 覆盖到旧文件夹（需先在托盘退出旧版）后打开，再点“后台服务 → 更新并启动”：安装新服务时同样会删除旧服务及上述文件。旧版 AHK 连发没有单实例锁，所以它还在运行时新版不会同时打开（会提示先退出旧版或选择升级），避免同一个键被连发两次。

### 服务做什么

- **游戏检测**：每隔“检测间隔”秒查找游戏进程（默认 `DNF.exe`），不需要填写游戏安装路径。
- **随游戏启动**：游戏启动后立即在同一登录会话中启动列表里的程序，已在运行的不会重复启动。相对路径以 `DNFAutoFire.exe` 所在目录为准，默认就是连发程序本身。
- **延迟结束 / 限制资源**：等待“启动后延迟处理”秒（默认 60）后，结束“延迟结束的进程”（只结束该进程本身，不结束进程树），并把“限制资源的进程”绑定到最后一个 CPU 核心、降为极低 I/O 优先级。
- **保持游戏优先级**：游戏运行期间保持“正常”或“高于正常”。不会使用“高”或“实时”，过高的优先级反而会挤压声音、输入和驱动。
- **游戏退出后关闭**：只关闭同一登录会话中的程序，不影响其他用户。
- **关闭 DNF 启动器**：只有在同一会话里真的运行过 DNF、并且游戏退出一分钟后启动器仍在运行时，才会结束通过身份校验（路径、会话、启动时间、目录结构、DNF 更新清单）的启动器；只打开启动器下载或更新游戏时不会关闭。启动器运行期间，服务会把它的 `AppData\config.json` 保持为“游戏退出后不弹出主窗口、关闭时最小化”。

“随游戏启动”里的连发程序本身带锁形标记，不能移除，保证游戏启动时总能打开连发。

进程名不用手动输入：点击“游戏进程”或列表后的“选择进程…”会列出正在运行的程序（带完整路径，标“后台”的是服务进程），可搜索、可连续勾选；列表里没有的进程也可以在搜索框输入名称后按回车添加。“随游戏启动”点击“选择程序…”弹出文件选择框，选中本程序目录里的文件时自动保存为相对路径。

所有选项都在“服务管理”里修改，自动保存到 `config.json`，服务约 1 秒内读取，无需重启服务。

### 查看日志

服务日志位于程序目录的 `logs\service.log`，“服务管理”底部的“打开服务日志”可以直接打开。日志超过 128 KB 时滚动为 `service.log.1`，最多保留两个文件。常见提示：

- `随游戏启动的程序不存在`：路径写错，或文件没有放在程序目录。
- `无法在用户会话 … 启动`：登录会话或权限异常，可在“服务管理”中重启服务后再试。
- `已创建为进程 …，但随即退出`：程序被创建后马上退出，可以手动双击它查看提示。
- `无法结束进程`：目标进程拒绝结束（例如受保护的系统组件）。

## 配置文件 config.json

v0.3.0.0 起，连发方案、软件设置和服务设置全部保存在 `DNFAutoFire.exe` 同目录的 **一个** `config.json`（UTF-8）中：

```json
{
  "version": 1,
  "settings": { "autoStart": true, "lastProfile": "普通", "quickSwitchHotkey": "!PgUp", "theme": "dark", "oneKeyRun": { … } },
  "profiles": [ { "name": "普通", "keys": ["X", "Z", "A", "Num0"], "downMs": 7, "upMs": 7, … } ],
  "service": {
    "gameProcess": "DNF.exe",
    "pollSeconds": 2,
    "actionDelaySeconds": 60,
    "closeLauncherAfterGame": true,
    "optimizeGamePriority": true,
    "gamePriority": "AboveNormal",
    "limit": ["SGuard64.exe", "SGuardSvc64.exe", "CrossProxy.exe"],
    "kill": ["GameLoader.exe", "TXPlatform.exe"],
    "autoStart": ["DNFAutoFire.exe"],
    "autoStop": ["DNFAutoFire.exe"]
  }
}
```

- 推荐在界面里修改；手动编辑时请保持合法 JSON（英文双引号、逗号分隔，路径中的 `\` 写成 `\\`）。文件格式错误时程序会提示出错的行和列，不会覆盖你的文件。
- 首次启动时，同目录的 `config.ini`（连发）和 `appsettings.json`（旧服务）会被合并进来，写入并校验成功后才删除旧文件；`appsettings.Development.json` 一并删除。本版本不认识的旧字段保存在 `legacyIni` 中，不会丢失。已经有 `config.json` 时，后来出现的旧文件不会覆盖它。
- 更新程序时只替换 `DNFAutoFire.exe`，保留 `config.json`。

## 游戏工具箱

原 `DNF专用工具箱8.0.bat` 的功能已经放进程序：点击顶栏的扳手图标打开“游戏工具箱”，不再需要把脚本复制到游戏目录。

- **游戏目录**：打开时自动识别，依次查找上次使用的目录、正在运行的 DNF、DNF 启动器、注册表和常见安装位置（如 `WeGameApps\地下城与勇士：创新世纪`）。识别失败时点击“选择目录…”，选中包含 `DNF.exe`、`start` 和 `Pandora` 的游戏根目录；结果会记住。
- **禁用无用组件 / 恢复全部**：处理 Install.dll、TP3Helper.exe、TGuard、启动器广告、井盖（Pandora 9193 / GRobot）以及 `%APPDATA%\Tencent` 下的 AndroidAssist、QQDoctor、TCLSCore 等组件。每一项的当前状态都会列出来。备份和标记文件名与 8.0 脚本完全相同，以前用脚本禁用过的组件也能在这里恢复。
- **清理日志与缓存**：删除游戏日志、崩溃记录和用户缓存，保留 `DNF.cfg` 画面设置。
- **修复黑屏 / 连接服务器**：清空 `LocalLow\DNF` 全部用户缓存（包括 `DNF.cfg`）。
- 清理和修复需要点两次确认；所有文件操作都要求先关闭 DNF。下载与更新组件（BackgroundDownloader、Tencentdl、TenioDL、TesService、QQDownload、QQMiniDL、DeskUpdate、TXPTOP、TXFTN）始终不会被改动。

## 界面动效

抽屉滑入滑出、遮罩渐变、切换抽屉时内容交叉淡入、滚动平滑缓动；开关滑块、启动按钮、分段选择和方案标签的高亮都会平滑过渡；键帽按下、悬停和绿灯亮灭，菜单、进程选择浮层、快速切换窗口和托盘菜单的淡入，以及处理中的加载指示，都有过渡动画。Windows“设置 → 辅助功能 → 视觉效果 → 动画效果”关闭时，程序同样不播放动画。

## 更新日志

### 2026-9-25 v0.3.0.1

- [服务]服务运行时删除或移动 `DNFAutoFire.exe`，Windows“文件正在使用”提示中直接写明如何停止：服务显示名改为“DNF 连发后台服务（删除或移动程序前：打开连发 → 后台服务 → 卸载）”，服务说明给出完整步骤与 `sc` 命令；已安装的旧服务在下次启动时自动刷新。
- [构建]版本号自动递增：源码变化后构建即把第四位加一，`native/version.h` 成为代码中唯一的版本来源；GitHub Release 改为只在推送 `v*` 标签时发布。

### 2026-9-25 v0.3.0.0

- [合并]原 DNF Process Manager（.NET 服务）的全部功能用 C++ 重写并入本程序：同一个 `DNFAutoFire.exe` 既是连发界面，也以 `--service` 方式作为 Windows 服务运行，不再需要 `DNFProcessManager.exe`、`服务管理.bat` 和 .NET 运行环境。
- [工具箱]原 DNF专用工具箱 8.0 并入程序（顶栏扳手图标）：自动识别游戏根目录（失败时手动选择并记住），禁用 / 恢复无用组件并逐项显示状态，清理日志缓存与修复黑屏；与 8.0 脚本的备份和标记完全兼容，不改动下载与更新组件。
- [界面]全面加入过渡动画：抽屉滑入滑出与内容交叉淡入、平滑滚动、开关与启动按钮渐变、分段选择与方案标签高亮滑动、键帽按压与绿灯渐亮、菜单 / 浮层 / 快速切换 / 托盘菜单淡入、处理中指示；遵循系统“动画效果”设置。
- [升级]支持直接替换旧版组合（AHK 连发 + DNFProcessManager 服务 + config.ini / appsettings.json）：双击新版本即识别旧服务启动的连发或运行中的 AHK 版，停止旧服务、让旧版连发自行退出、原位替换、合并配置为 config.json，安装新服务后删除旧服务程序、`服务管理.bat`、`DNF专用工具箱8.0.bat`、旧配置与旧服务日志；在服务管理中“更新并启动”替换旧服务时同样清理；旧版 AHK 运行时不再同时启动新版。
- [更新]已安装服务时可以直接更新程序：双击新版本 EXE 会提示更新已安装的副本，或在“服务管理 · 程序版本”中“从文件更新…”；自动停止服务和连发（先释放按键）、原位替换文件（失败自动恢复）、重新打开新版本并重启服务，配置与服务设置不变，不保留旧文件，路径均取自服务注册与运行中的程序。
- [服务]“随游戏启动”列表中的连发程序本身锁定，不能移除。
- [服务]进程名从正在运行的进程列表中选择（搜索、连续添加、已添加项标记，也可回车手动添加）；随游戏启动的程序通过文件选择框选择，本程序目录内自动转为相对路径。
- [服务]新增“服务管理”侧栏，沿用现有键帽与主题风格：安装 / 更新并启动、启动、停止、重启、卸载（二次确认）。主界面“启动连发”开关左侧显示后台服务状态（绿灯运行中、黄灯需更新、红灯未安装 / 未运行，悬停底栏说明），点击即打开侧栏，状态实时刷新；连发未启动时底栏与键盘指示区的“连发”灯为红色；安装时自动停止并删除旧版 DNFProcessManager / AutoManagerProcess 服务，并设置异常退出后自动重启。
- [服务]游戏启动后使用登录用户的管理员令牌在游戏会话中打开连发，不再弹出 UAC；游戏退出时通过跨会话事件让连发自行停止并释放按键，5 秒未退出才强制结束。
- [服务]保留原有行为：游戏进程检测、延迟结束 / 限制指定进程、保持“正常 / 高于正常”优先级、游戏退出后关闭指定程序、游戏运行过并退出一分钟后关闭通过身份校验的 DNF 启动器并保持其退出设置。
- [配置]`config.ini` 与 `appsettings.json` 合并为一个 UTF-8 的 `config.json`：内存缓存、仅在文件变化时重新读取、原子替换写入并以全局互斥锁串行化；首次启动自动迁移，校验成功后删除旧文件，未知字段保留。服务约 1 秒内读取修改，无需重启。
- [日志]服务日志 `logs\service.log`，128 KB 滚动，最多保留两个文件。
- [验证]新增 JSON、配置迁移和服务逻辑回归（含子进程模拟的游戏生命周期）；新增系统依赖 WTSAPI32、USERENV 已加入导入白名单。
- [文档]新增图文操作手册 `docs/操作手册.md`（面向普通玩家，每个功能一张标注截图）；“随游戏启动”列表中的锁形标记改为实心锁身，小尺寸下也清晰可辨。
